
## Performance & Memory Comparison (M4)

|-------------------|-----------|------------------|------------------|

| lazy (generators) | 1000      | 1.43             | 0.688            |
### Memory Footprint Explanation

Суттєва різниця у піковому використанні пам'яті пояснюється тим, як дані рухаються через пайплайн. 
У жадібній версії (eager) програма спочатку зчитує весь корпус у список об'єктів `Document`, 
а потім створює ще один гігантський список списків токенів `list[list[str]]`, 
одночасно утримуючи всі дані в оперативній пам'яті (N) від обсягу корпусу).
Натомість у потоковій версії (lazy) завдяки Python-генераторам (`yield`) у пам'яті в 
кожен момент часу перебуває лише один файл та один токен.
Головним споживачем пам'яті в `lazy`-підході залишається тільки структура `Counter` для 
збереження унікального словника, що робить витрати RAM практично незалежними від 
загального розміру вихідного корпусу.
